Gambaran

Apa yang dikerjakan badan

Badan robot dikendalikan ESP32 DevKit V1 di papan ekspansi 30P. Ia menggerakkan roda dan kepala, membaca semua sensor, dan menjalankan aturan keselamatan sendiri. Otak (ESP32-S3) hanya mengirim perintah singkat seperti M 150 150 800 (maju 0,8 detik).

Tahap 1

Siapkan DevKit di papan 30P

DevKit V1Papan ekspansi 30PKabel micro-USB dataMultimeter
  • 1 Blok daya: kolom kiri semua GND, kolom kanan berisi pin 5V dan 3V (cek di langkah 3). Di mode jalan, 5 V dari LM2596 masuk ke salah satu pin 5V ini.
  • 2 Jumper pemilih tegangan pin V: pindahkan ke posisi 3.3V–V. Semua pin V di papan lalu bertegangan 3,3 V.
  • 3 dan 4: baris pin tiap GPIO (S = sinyal paling luar, V, G). Nama baris tercetak di sampingnya: D25, D26, D23, D22, dan seterusnya.
  • 5 Header I2C: D22, D21, VCC, GND. Dipakai MPU6050 di Tahap 6.
  • 6 Jack DC 6,5-16 V: tidak dipakai. 7 Port USB papan: hanya daya, tidak dipakai. Upload lewat port micro-USB di modul DevKit.
Berhasil kalau

Kode kedip berjalan di DevKit, dan kamu sudah tahu pin mana yang 5 V dan mana yang 3,3 V di blok daya.

Kalau tidak berhasil
  • Port tidak muncul: kabel USB-mu mungkin kabel charge saja. Coba kabel lain. Chip USB di DevKit V1 umumnya CP2102: install driver CP210x kalau perlu.

Sisi daya TB6612: 6 V dari XL4015 ke VM, dua motor paralel per kanal.

tes_motor.inoUnduh
// TES MOTOR: roda kiri maju, kiri mundur, kanan maju, kanan mundur. Roda harus TERANGKAT.
#define PWMA 25
#define AIN1 26
#define AIN2 27
#define PWMB 13
#define BIN1 32
#define BIN2 33

void motor(int pwm, int in1, int in2, int v) {
  digitalWrite(in1, v > 0); digitalWrite(in2, v < 0);
  ledcWrite(pwm, abs(v));
}

void setup() {
  Serial.begin(115200);
  pinMode(AIN1, OUTPUT); pinMode(AIN2, OUTPUT); pinMode(BIN1, OUTPUT); pinMode(BIN2, OUTPUT);
  ledcAttach(PWMA, 20000, 8);
  ledcAttach(PWMB, 20000, 8);
}

void loop() {
  Serial.println("KIRI maju");    motor(PWMA, AIN1, AIN2, 150);  delay(1500); motor(PWMA, AIN1, AIN2, 0); delay(700);
  Serial.println("KIRI mundur");  motor(PWMA, AIN1, AIN2, -150); delay(1500); motor(PWMA, AIN1, AIN2, 0); delay(700);
  Serial.println("KANAN maju");   motor(PWMB, BIN1, BIN2, 150);  delay(1500); motor(PWMB, BIN1, BIN2, 0); delay(700);
  Serial.println("KANAN mundur"); motor(PWMB, BIN1, BIN2, -150); delay(1500); motor(PWMB, BIN1, BIN2, 0);
  Serial.println("--- jeda 3 detik ---"); delay(3000);
}

Kenapa begitu? PWMA mengatur kecepatan (0-255) dengan menyalakan-mematikan sangat cepat (20.000 kali per detik). AIN1 dan AIN2 mengatur arah: satu HIGH satu LOW = berputar, keduanya sama = berhenti.

Berhasil kalau

Serial Monitor menulis KIRI maju, KIRI mundur, KANAN maju, KANAN mundur, dan roda yang sesuai berputar ke arah itu. "Maju" = roda berputar seperti robot berjalan ke depan.

Kalau tidak berhasil
  • Satu sisi berputar terbalik: tukar dua kabel motor sisi itu di AO1/AO2 (atau BO1/BO2). Atau nanti ubah MOTOR_KIRI_TERBALIK di kode badan.
  • Satu roda di sisi yang sama berputar berlawanan dengan roda lainnya: tukar merah-hitam motor itu saja.
  • Tidak ada roda yang berputar: STBY belum ke 3V, VM belum dapat 6 V, atau GND DevKit tidak tersambung ke GND TB6612.
  • Roda berdengung tapi tidak berputar: kecepatan 150 terlalu kecil untuk motormu, atau XL4015 kurang dari 6 V.
  • DevKit restart saat motor mulai: noise motor. Pasang kapasitor 100 nF di motor dan cek GND bersama.
Tahap 4

Kepala pan-tilt (servo MG90S)

Pan-tilt dengan 2 MG90SKabel M-F dan M-MKapasitor 470 µFRel 6 V
tes_servo.inoUnduh
// TES SERVO: kepala menoleh kiri-tengah-kanan, lalu mengangguk.
// Ketik dua angka di Serial Monitor, misalnya "90 90" lalu Enter, untuk mengatur sendiri.
#define PAN  23
#define TILT 4

void sudut(int pin, int derajat) {
  int us = map(derajat, 0, 180, 600, 2400);        // lebar pulsa 0,6 - 2,4 ms
  ledcWrite(pin, (uint32_t)us * 16383 / 20000);    // 50 Hz, resolusi 14 bit
}

void setup() {
  Serial.begin(115200);
  ledcAttach(PAN, 50, 14);
  ledcAttach(TILT, 50, 14);
  sudut(PAN, 90); sudut(TILT, 90);
  delay(1000);
  int urutan[] = {90, 45, 90, 135, 90};
  for (int s : urutan) { Serial.printf("pan %d\n", s); sudut(PAN, s); delay(800); }
  int angguk[] = {90, 60, 110, 90};
  for (int s : angguk) { Serial.printf("tilt %d\n", s); sudut(TILT, s); delay(800); }
  Serial.println("Selesai. Ketik: pan tilt  (contoh: 90 70)");
}

void loop() {
  if (Serial.available()) {
    int p = Serial.parseInt(), t = Serial.parseInt();
    p = constrain(p, 0, 180); t = constrain(t, 40, 150);
    sudut(PAN, p); sudut(TILT, t);
    Serial.printf("pan %d  tilt %d\n", p, t);
    while (Serial.available()) Serial.read();
  }
}

Kenapa begitu? Servo membaca lebar pulsa 50 kali per detik: 0,6 ms = 0°, 1,5 ms = 90°, 2,4 ms = 180°. Sudut tilt dibatasi 40-150° di kode supaya kepala tidak membentur bracket.

Berhasil kalau

Kepala menoleh ke kiri, tengah, kanan, lalu mengangguk. Ketik 90 90 di Serial Monitor: kepala lurus ke depan.

Kalau tidak berhasil
  • Servo bergetar atau berdengung terus: daya kurang. Pastikan merah ke 6 V (bukan 3,3 V) dan kapasitor terpasang.
  • Kepala menabrak bracket di sudut tertentu: catat sudutnya, nanti ubah TILT_MIN dan TILT_MAX di kode badan.
Tahap 5

Dua sensor jarak HC-SR04

2 HC-SR04Breadboard kecil2 resistor 1 kΩ2 resistor 2 kΩKabel F-F, F-M, M-M

Geser gambar ke samping untuk melihat semuanya.

Bagian yang baru dipasang tampil terang, bagian tahap sebelumnya pudar. Titik putih = ujung kaki atau kabel di lubang. Tag di tepi atas/bawah = kabel keluar ke board atau sensor.

Geser gambar ke samping untuk melihat semuanya.

tes_jarak.inoUnduh
// TES SENSOR JARAK: cetak jarak depan dan belakang dalam cm.
#define TRIG_D 18
#define ECHO_D 19
#define TRIG_B 14
#define ECHO_B 35

int jarak(int trig, int echo) {
  digitalWrite(trig, LOW);  delayMicroseconds(3);
  digitalWrite(trig, HIGH); delayMicroseconds(10);
  digitalWrite(trig, LOW);
  unsigned long d = pulseIn(echo, HIGH, 25000UL);   // tunggu maks 25 ms (~4 m)
  return d ? d / 58 : -1;                            // -1 = tidak ada pantulan
}

void setup() {
  Serial.begin(115200);
  pinMode(TRIG_D, OUTPUT); pinMode(ECHO_D, INPUT);
  pinMode(TRIG_B, OUTPUT); pinMode(ECHO_B, INPUT);
}

void loop() {
  int d = jarak(TRIG_D, ECHO_D);
  delay(40);                                         // jeda supaya gema sensor depan tidak terbaca sensor belakang
  int b = jarak(TRIG_B, ECHO_B);
  Serial.printf("depan: %4d cm   belakang: %4d cm\n", d, b);
  delay(300);
}

Kenapa begitu? Sensor mengirim bunyi ultrasonik, lalu pin ECHO menyala selama bunyi pergi-pulang. Suara menempuh sekitar 1 cm per 29 µs, pergi-pulang 58 µs per cm. Dua sensor dibaca bergantian supaya gema yang satu tidak terbaca yang lain.

Berhasil kalau

Angka depan dan belakang berubah saat tanganmu mendekat. Coba ke tembok: angkanya mendekati jarak yang diukur dengan penggaris (selisih 1-2 cm wajar). -1 berarti tidak ada pantulan (terlalu jauh, atau sensor tidak tersambung).

Kalau tidak berhasil
  • Selalu -1: VCC belum dapat 5 V (cek a30), atau TRIG/ECHO tertukar.
  • Angka melompat-lompat: permukaan miring atau lembut (kain, sofa) memantulkan bunyi buruk. Itu sifat sensor ini.
  • Selalu 0 atau angka kecil tetap: resistor 2 kΩ belum ke garis biru.

Geser gambar ke samping untuk melihat semuanya.

Bagian yang baru dipasang tampil terang, bagian tahap sebelumnya pudar. Titik putih = ujung kaki atau kabel di lubang. Tag di tepi atas/bawah = kabel keluar ke board atau sensor.

tes_i2c.inoUnduh
// TES I2C: cari alamat perangkat, lalu baca MPU6050 (kemiringan) dan BME280 atau DHT11 (cuaca).
// Alamat yang benar: 0x68 = MPU6050, 0x76 atau 0x77 = BME280.
#include <Wire.h>
#include <Adafruit_BME280.h>
#include <DHT.h>

Adafruit_BME280 bme;
DHT dht(5, DHT11);
bool adaBME = false, adaMPU = false;

void setup() {
  Serial.begin(115200);
  delay(500);
  Wire.begin(21, 22);
  Serial.println("Mencari perangkat I2C...");
  for (byte a = 1; a < 127; a++) {
    Wire.beginTransmission(a);
    if (Wire.endTransmission() == 0) Serial.printf("  ditemukan di 0x%02X\n", a);
  }
  Wire.beginTransmission(0x68);
  adaMPU = Wire.endTransmission() == 0;
  if (adaMPU) { Wire.beginTransmission(0x68); Wire.write(0x6B); Wire.write(0); Wire.endTransmission(); }
  adaBME = bme.begin(0x76) || bme.begin(0x77);
  if (!adaBME) dht.begin();
  Serial.printf("MPU6050: %s   BME280: %s\n", adaMPU ? "ada" : "TIDAK", adaBME ? "ada" : "TIDAK (pakai DHT11 di GPIO 5)");
}

void loop() {
  if (adaMPU) {
    Wire.beginTransmission(0x68); Wire.write(0x3B); Wire.endTransmission(false);
    Wire.requestFrom(0x68, 6);
    int16_t ax = (Wire.read() << 8) | Wire.read();
    int16_t ay = (Wire.read() << 8) | Wire.read();
    int16_t az = (Wire.read() << 8) | Wire.read();
    float pitch = atan2(-ax, sqrt((float)ay * ay + (float)az * az)) * 57.3;
    float roll  = atan2(ay, az) * 57.3;
    Serial.printf("pitch %6.1f  roll %6.1f   ", pitch, roll);
  }
  if (adaBME) Serial.printf("suhu %.1f C  lembap %.0f %%  tekanan %.0f hPa\n", bme.readTemperature(), bme.readHumidity(), bme.readPressure() / 100);
  else Serial.printf("suhu %.1f C  lembap %.0f %%\n", dht.readTemperature(), dht.readHumidity());
  delay(1000);
}

Kenapa begitu? MPU6050 mengukur percepatan, termasuk gravitasi. Dari arah gravitasi, kode menghitung seberapa miring robot. Badan memakai ini untuk berhenti kalau robot terbalik atau terangkat miring.

Berhasil kalau

Pencarian menemukan 0x68 (MPU6050) dan, kalau ada, 0x76 atau 0x77 (BME280). Pitch dan roll mendekati 0 saat datar dan berubah saat dimiringkan. Suhu dan kelembapan masuk akal.

Kalau tidak berhasil
  • Tidak ada alamat ditemukan: SDA dan SCL tertukar, atau VCC belum tersambung.
  • BME280 tidak terbaca padahal alamat ada di 0x76/0x77: modulmu mungkin BMP280 (tanpa kelembapan). Tulisan di chip kecilnya membedakan.
  • "nan" untuk DHT11: cek urutan kaki dan resistor 10 kΩ.

Geser gambar ke samping untuk melihat semuanya.

Bagian yang baru dipasang tampil terang, bagian tahap sebelumnya pudar. Titik putih = ujung kaki atau kabel di lubang. Tag di tepi atas/bawah = kabel keluar ke board atau sensor.

Geser gambar ke samping untuk melihat semuanya.

tes_baterai.inoUnduh
// TES BATERAI DAN TOMBOL STOP
// Baterai lewat pembagi 20k/10k ke GPIO 34. Tombol ke GPIO 39 (+ resistor 10k ke 3V3).
float FAKTOR = 3.0;      // ubah setelah dibandingkan dengan multimeter (lihat panduan)

void setup() {
  Serial.begin(115200);
  pinMode(39, INPUT);
  analogSetPinAttenuation(34, ADC_11db);
}

void loop() {
  uint32_t mv = 0;
  for (int i = 0; i < 16; i++) mv += analogReadMilliVolts(34);
  mv /= 16;
  Serial.printf("pin 34: %4u mV  ->  baterai: %.2f V   tombol: %s\n",
                mv, mv / 1000.0 * FAKTOR, digitalRead(39) == LOW ? "DITEKAN" : "lepas");
  delay(500);
}

Kenapa begitu? GPIO 39 hanya bisa input dan tidak punya resistor pull-up di dalam chip, jadi kita pasang 10 kΩ ke 3,3 V. Tanpa ditekan pin membaca HIGH; ditekan, pin tersambung ke GND dan membaca LOW. Untuk robot jadi, ganti tombol 6 mm dengan tombol 12 mm yang ditempel di plat atas, disambung dua kabel ke kolom 27 dan 29.

Berhasil kalau

Tegangan baterai di Serial Monitor sama dengan multimeter (selisih di bawah 0,1 V setelah kalibrasi), dan tulisan berubah ke DITEKAN saat tombol ditekan.

Kalau tidak berhasil
  • Baterai terbaca 0: kabel BAT+ belum masuk a20, atau saklar OFF.
  • Tombol selalu DITEKAN: kaki tombol yang dipakai bukan diagonal. Putar tombol 90 derajat.

Upload kode badan dan uji keselamatan

robot_badan.ino (bagian awal: penjelasan, pengaturan, pin)
/*
  ROBOT AI 4WD - BADAN (ESP32 DevKit V1)
  ---------------------------------------
  Mengurus: 4 motor TT lewat TB6612FNG, servo pan-tilt, 2 sensor jarak HC-SR04,
  MPU6050 (kemiringan), BME280 atau DHT11 (cuaca), tombol STOP, dan tegangan baterai.
  Menerima perintah teks dari ESP32-S3 (otak) lewat UART2, atau dari Serial Monitor.

  Board di Arduino IDE : ESP32 Dev Module
  Library             : Adafruit BME280 Library, DHT sensor library (Adafruit)
                        (keduanya otomatis meminta "Adafruit Unified Sensor" dan "Adafruit BusIO", pilih Install All)

  PERINTAH (satu baris, diakhiri Enter / newline):
    M <kiri> <kanan> [ms]   gerak. kiri/kanan -255..255. ms = lama (default 600, maks 3000)
    S                       berhenti
    P <pan> <tilt>          arahkan kepala, derajat 0..180
    Q                       minta data sekarang
    PING                    balas PONG
  BALASAN otomatis tiap 250 ms:
    D <depan_cm> <belakang_cm> <baterai_V> <suhu_C> <lembap_%> <pitch> <roll> <flag>
    flag: 1=STOP ditekan, 2=baterai lemah, 4=halangan depan, 8=halangan belakang, 16=miring
    Nilai -1 = sensor tidak terpasang / gagal baca.

  Aturan keselamatan ada DI SINI, bukan di otak:
    - Setiap gerakan berhenti sendiri setelah waktunya habis (otak hang = robot berhenti).
    - Halangan < JARAK_STOP_DEPAN cm: tidak boleh maju. Halangan belakang: tidak boleh mundur.
    - Tombol STOP: tekan sekali = kunci berhenti, tekan lagi = lepas.
    - Baterai di bawah BATERAI_MIN: motor dimatikan sampai board di-restart.
    - Miring lebih dari 40 derajat (terbalik/terangkat miring): motor berhenti.
*/

#include <Wire.h>
#include <Adafruit_BME280.h>
#include <DHT.h>

// ================== PENGATURAN (boleh diubah) ==================
const int   JARAK_STOP_DEPAN    = 20;    // cm
const int   JARAK_STOP_BELAKANG = 15;    // cm
const float BATERAI_MIN         = 6.4;   // volt total 2 sel (3,2 V per sel)
float       BATERAI_FAKTOR      = 3.0;   // pembagi 20k/10k. Kalibrasi: lihat panduan Tahap 6
const bool  MOTOR_KIRI_TERBALIK  = false; // ubah ke true kalau roda kiri berputar terbalik
const bool  MOTOR_KANAN_TERBALIK = false;
const int   SERVO_MIN_US = 600;          // lebar pulsa sudut 0
const int   SERVO_MAX_US = 2400;         // lebar pulsa sudut 180
const int   TILT_MIN = 40, TILT_MAX = 150; // batasi supaya kepala tidak membentur bracket

// ================== PIN (sesuai panduan) ==================
#define PIN_PWMA   25   // TB6612 kanal A = motor kiri
#define PIN_AIN1   26
#define PIN_AIN2   27
#define PIN_PWMB   13   // TB6612 kanal B = motor kanan
#define PIN_BIN1   32
#define PIN_BIN2   33
#define PIN_PAN    23   // servo pan (kiri-kanan)
#define PIN_TILT    4   // servo tilt (atas-bawah)
#define PIN_TRIG_D 18   // HC-SR04 depan
#define PIN_ECHO_D 19   // lewat pembagi 1k/2k!
#define PIN_TRIG_B 14   // HC-SR04 belakang
#define PIN_ECHO_B 35   // lewat pembagi 1k/2k! (GPIO 35 hanya input, cocok untuk ECHO)
#define PIN_TOMBOL 39   // tombol STOP ke GND + resistor 10k ke 3V3 (GPIO 39 tidak punya pull-up internal)
#define PIN_BATT   34   // pembagi 20k (ke baterai) / 10k (ke GND)
#define PIN_DHT     5   // DHT11, hanya dipakai kalau BME280 tidak ditemukan
#define PIN_LED     2   // LED biru bawaan DevKit
#define PIN_RX2    16   // dari TX ESP32-S3 (GPIO 17)
#define PIN_TX2    17   // ke RX ESP32-S3 (GPIO 18)

Kode lengkap: unduh robot_badan.ino.

Kenapa begitu? Baris D berisi jarak depan, jarak belakang, baterai, suhu, kelembapan, pitch, roll, dan flag. Otak membaca baris yang sama lewat UART tiap 250 ms. Semua gerakan berhenti sendiri setelah waktunya habis (maks 3 detik), jadi kalau otak macet atau kabel UART lepas, robot tidak lari.

Berhasil kalau

Badan menuruti perintah dan menolak gerakan berbahaya. Di Serial Monitor tiap detik muncul baris data seperti D 45 120 7.92 29.5 70 1 -2 0.
