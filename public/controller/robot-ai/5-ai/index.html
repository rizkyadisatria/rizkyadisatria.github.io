Batas gratis Gemini

Gemini dipakai lewat Google AI Studio tanpa kartu kredit. Batasnya dihitung per proyek dan per model (permintaan per menit dan per hari), dan Google tidak lagi mengumumkannya di dokumentasi: angka yang berlaku untukmu hanya terlihat di halaman batas AI Studio dan bisa berubah sewaktu-waktu. Jatah harian kembali penuh tengah malam waktu Pasifik, sekitar pukul 15.00-16.00 WITA.

Contoh jatah gratis yang terlihat di satu akun pada November 2026: Gemini 3.5 Flash Lite 15 per menit dan 500 per hari, Gemma 4 31B 30 per menit dan 14.400 per hari, sedangkan Gemini 2.5 Flash Lite hanya 20 per hari. Kode memakai Gemini 3.5 Flash Lite sebagai otak utama dan Gemma 4 31B (kunci yang sama) sebagai cadangan pertama.

Satu obrolan robot = satu permintaan; pertanyaan yang membuat robot memotret biasanya dua (memutuskan melihat, lalu menjelaskan fotonya). Kalau jatah Gemini habis, robot otomatis pindah ke Gemma, lalu ke Groq kalau kunci Groq diisi (Tahap 3). Di tingkat gratis, Google boleh memakai isi pertanyaan dan foto untuk memperbaiki layanannya; jangan kirim hal yang pribadi.

tes_telegram.inoUnduh
// TES WIFI + TELEGRAM: bot membalas setiap pesanmu. Library: UniversalTelegramBot, ArduinoJson
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <UniversalTelegramBot.h>

const char* WIFI_NAMA      = "NAMA_WIFI";
const char* WIFI_PASSWORD  = "PASSWORD_WIFI";
const char* TOKEN          = "ISI_TOKEN_DARI_BOTFATHER";
const char* CHAT_ID        = "ISI_ANGKA_ID_KAMU";

WiFiClientSecure client;
UniversalTelegramBot bot(TOKEN, client);

void setup() {
  Serial.begin(115200);
  delay(1500);   // beri waktu Serial Monitor tersambung
  Serial.println("\n=== TES TELEGRAM ===");
  WiFi.begin(WIFI_NAMA, WIFI_PASSWORD);
  Serial.print("WiFi");
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.print("\nTersambung, IP "); Serial.println(WiFi.localIP());
  client.setCACert(TELEGRAM_CERTIFICATE_ROOT);
  bool ok = bot.sendMessage(CHAT_ID, "Halo dari ESP32-S3! Kirim pesan apa saja.");
  Serial.println(ok ? "Pesan terkirim ke Telegram" : "GAGAL kirim. Cek token dan chat ID");
}

void loop() {
  int n = bot.getUpdates(bot.last_message_received + 1);
  for (int i = 0; i < n; i++) {
    Serial.println("Pesan masuk: " + bot.messages[i].text);
    bot.sendMessage(bot.messages[i].chat_id, "Kamu bilang: " + bot.messages[i].text);
  }
  delay(1000);
}
Berhasil kalau

Bot mengirim "Halo dari ESP32-S3!" dan membalas setiap pesanmu.

Setelah lulus: boleh dipatenkan atau belum?

Boleh dipatenkan Token bot dan chat ID.

Jangan dulu Jangan diunggah ke GitHub atau dikirim ke orang lain. Kalau bocor, buat bot baru.

Kalau tidak berhasil
  • "GAGAL kirim": token salah ketik (harus lengkap dengan angka dan titik dua), chat ID salah, atau belum menekan Start di bot.
  • WiFi tidak tersambung: ESP32 hanya bisa 2.4 GHz.

tes_gemini.inoUnduh
// TES GEMINI API: ketik pertanyaan di Serial Monitor, jawaban AI muncul di bawahnya.
// Library: ArduinoJson. Butuh API key gratis dari aistudio.google.com (diawali AIza).
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>

const char* WIFI_NAMA     = "NAMA_WIFI";
const char* WIFI_PASSWORD = "PASSWORD_WIFI";
const char* API_KEY       = "ISI_API_KEY_GEMINI";
const char* MODEL         = "gemini-3.5-flash-lite";   // samakan dengan GEMINI_MODEL di robot_otak; coba juga "gemma-4-31b-it"

String tanya(const String& q) {
  JsonDocument doc;
  doc["system_instruction"]["parts"][0]["text"] = "Jawab dalam Bahasa Indonesia, singkat, paling banyak 2 kalimat.";
  JsonObject m = doc["contents"].to<JsonArray>().add<JsonObject>();
  m["role"] = "user"; m["parts"][0]["text"] = q;
  String body; serializeJson(doc, body);

  WiFiClientSecure c; c.setInsecure();     // terenkripsi, tapi sertifikat server tidak diperiksa
  HTTPClient http;
  http.begin(c, String("https://generativelanguage.googleapis.com/v1beta/models/") + MODEL + ":generateContent");
  http.addHeader("content-type", "application/json");
  http.addHeader("x-goog-api-key", API_KEY);
  http.setTimeout(30000);
  int code = http.POST(body);
  String resp = http.getString();
  http.end();
  if (code != 200) return "GAGAL (kode " + String(code) + "): " + resp;
  JsonDocument r; deserializeJson(r, resp);
  String teks;
  for (JsonObject p : r["candidates"][0]["content"]["parts"].as<JsonArray>())
    if (!(p["thought"] | false)) teks += p["text"] | "";
  return teks.length() ? teks : "(kosong): " + resp;
}

void setup() {
  Serial.begin(115200);
  delay(1500);   // beri waktu Serial Monitor tersambung
  Serial.println("\n=== TES GEMINI ===");
  WiFi.begin(WIFI_NAMA, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.println("\nSiap. Ketik pertanyaan lalu Enter.");
}

void loop() {
  if (Serial.available()) {
    String q = Serial.readStringUntil('\n'); q.trim();
    if (q.length()) { Serial.println("Kamu: " + q); Serial.println("AI  : " + tanya(q)); }
  }
}

Kenapa begitu? Kode ini mengirim pertanyaan dalam format JSON ke alamat generativelanguage.googleapis.com lewat HTTPS, dengan kunci di header x-goog-api-key. Koneksinya terenkripsi, tapi demi kesederhanaan sertifikat server tidak diperiksa (setInsecure). Untuk proyek rumahan ini cukup; jangan pakai pola ini untuk data sensitif.

Berhasil kalau

Jawaban AI muncul dalam beberapa detik. Kode 400 dengan API_KEY_INVALID = kunci salah, 403 = kunci tidak diizinkan, 404 = nama model salah atau sudah tidak tersedia, 429 = jatah habis atau terlalu sering.

Setelah lulus: boleh dipatenkan atau belum?

Boleh dipatenkan API key Gemini dari AI Studio.

Jangan dulu Jangan taruh di berkas yang akan diunggah ke tempat publik.

Berhasil kalau

Layar menampilkan wajah dengan dua mata yang berkedip, baris status di atas berisi baterai dan jarak dari badan, speaker berkata "Halo, aku Zond. Aku siap.", dan bot mengirim "Zond menyala".

Setelah lulus: boleh dipatenkan atau belum?

Boleh dipatenkan robot_otak.ino yang sudah terisi (WiFi, token, chat ID, API key, KAMERA_ALAMAT, nama robot). Kalibrasi sentuh tersimpan di S3.

Jangan dulu Berkas yang sudah berisi kunci jangan diunggah ke tempat publik. Roda tetap terangkat.

Kalau tidak berhasil
  • Error kompilasi "Audio.h: No such file": library audio belum terpasang dari ZIP.
  • Error "Sketch too big" atau upload WiFi ditolak: Partition Scheme belum 3MB APP. Ganti, lalu upload sekali lewat USB.
  • Port jaringan tidak muncul di Tools → Port: tunggu sekitar 1 menit setelah robot menyala, tutup dan buka lagi Arduino IDE, atau upload lewat USB. Upload WiFi yang gagal di tengah tidak merusak apa pun: kode lama tetap jalan.
  • Restart terus dengan pesan PSRAM: menu PSRAM belum OPI PSRAM.
  • "badan belum terhubung" di layar: cek kabel UART dan GND (Bagian 3 Tahap 6).
  • Tidak bersuara tapi tes speaker berhasil: Google TTS mungkin sedang menolak. Jawaban tetap dikirim lewat Telegram.

Kalau tidak berhasil
  • AI menjawab tapi robot tidak bergerak: lihat Serial Monitor. Kalau ada "E DITOLAK", ada halangan atau tombol STOP terkunci.
  • Foto gagal: kamera menyala? IP di KAMERA_ALAMAT benar? Tab /stream di browser sudah ditutup?
  • Jadwal sholat beda 1-3 menit dari jadwal masjid setempat: isi SHOLAT_KOREKSI dengan menit tambahan untuk Imsak, Subuh, Terbit, Dzuhur, Ashar, Maghrib, Terbenam, Isya, Tengah malam, dipisah koma. Contoh "2,2,-2,2,2,2,0,2,0" menambah 2 menit ke waktu sholat dan mengurangi 2 menit dari waktu terbit.
  • Berita, kurs, atau jadwal sholat menulis "gagal diambil (kode -1)": WiFi lemah atau situsnya sedang sibuk. Keluar lalu buka lagi halamannya beberapa menit kemudian.
  • Tombol layar sering meleset: buka Setelan → Kalibrasi sentuh. Tekan di tengah tombol dan tahan sebentar; layar resistif butuh tekanan, bukan sentuhan ringan.
  • Mau kecerahan layar bisa diatur (dan redup sendiri di malam hari)? Cabut kabel LED layar dari rel 3,3 V, sambungkan ke IO38, lalu isi #define LAYAR_LED 38. Cek dulu ada transistor kecil (tiga kaki, tulisan Q1) di dekat pin LED modulmu; hampir semua modul merah 2,8" punya. Tanpa transistor, lampu layar menarik arus terlalu besar untuk pin S3.
  • Senter menulis "Kamera tidak menjawab": ESP32-CAM belum menyala, atau alamatnya belum ditemukan (isi IP kamera di KAMERA_ALAMAT). LED flash sengaja diredupkan di kode mata (analogWrite 60) supaya tidak panas; naikkan angkanya di robot_mata.ino kalau kurang terang, paling tinggi 255, dan jangan menyalakannya lama di nilai itu.
  • Rekaman terdengar pelan atau berdesis: mikrofon INMP441 menangkap paling jelas dari jarak 30-50 cm, dengan lubang kecilnya menghadap ke mulut. Desis halus adalah bising mikrofon, normal untuk modul ini.
  • Galeri menulis "Foto tidak bisa dibaca": file di /foto bukan JPEG dari kamera robot, atau ukurannya lebih dari 600 KB. Foto yang diambil Zond sendiri selalu bisa dibaca.
  • BICARA menghasilkan "Tidak terdengar jelas": bicara lebih dekat ke mikrofon, atau GROQ_API_KEY belum diisi.
  • Robot tidak menanggapi saat namanya disebut: lihat Serial Monitor. Baris "[dengar] tanpa nama, diabaikan" menunjukkan apa yang didengar; kalau namanya ditulis jauh berbeda, ganti NAMA_ROBOT dengan nama yang lebih jelas diucapkan. Robot juga tidak mendengar selama speaker berbunyi, termasuk saat musik atau radio diputar.
  • /belok menjawab "Badan belum punya giroskop": kode badan masih versi lama, robot berbelok memakai waktu (kurang tepat). Upload ulang robot_badan.ino. Menjawab "Roda selip atau macet": lantai licin, karpet tebal, atau baterai lemah.
  • Suit sering "tanganmu tidak terlihat jelas": ruangan kurang terang, atau tangan terlalu jauh atau terlambat ditunjukkan. Lihat foto kamera di panel web untuk memastikan tanganmu masuk gambar.
  • Jelajah terus menabrak kaki kursi atau meja: sensor ultrasonik tidak melihat benda tipis. Setelah 5 detik jarak depan tidak berubah, robot menganggap dirinya tersangkut lalu mundur dan berbalik. Untuk ruangan penuh kaki kursi, jelajahi ruangan lain.
  • Persen baterai naik-turun beberapa angka saat motor jalan: tegangan turun sesaat saat motor menarik arus. Angkanya dihaluskan, tapi perkiraan sisa waktu baru akurat setelah 10-30 menit.
  • Robot berkata "Jatah AI gratis sedang habis": batas harian Gemini (dan Groq kalau diisi) sudah terpakai. Tunggu jatahnya kembali sekitar pukul 15.00-16.00 WITA, atau pilih model lain dengan jatah lebih besar di halaman batas AI Studio.
Tahap 6

Suara cowok (opsional)

Kunci Gemini dari Tahap 2Laptop satu WiFi dengan robot

Kenapa begitu? Kode otak mengirim kalimat ke Gemini TTS dan menerima audio WAV 16 kHz dalam bentuk base64. Audio itu disimpan di memori flash S3 (partisi FATFS 9,9 MB yang sama dengan syarat upload lewat WiFi), lalu diputar. Karena suaranya dibuat dulu oleh AI, jeda sebelum bicara lebih lama daripada suara Google, sekitar 1-4 detik per kalimat. Kalau Gemini gagal, kalimat itu langsung diucapkan suara Google, jadi robot tidak pernah diam.

Berhasil kalau

Robot bicara dengan suara cowok. Serial Monitor menulis baris seperti [suara] Gemini 2100 ms, kalimat ke-12 hari ini.

Kalau tidak berhasil
  • Bot mengirim "Suara Gemini gagal (kode 429)": jatah gratis harian suara habis atau terlalu sering. Robot memakai suara Google dan mencoba Gemini lagi 5 menit kemudian. Batas jatahmu terlihat di halaman batas AI Studio.
  • Kode 400 atau 404: nama model atau nama suara salah ketik. Pesan dari Google ikut dikirim ke Telegram dan Serial Monitor. Kalau nama model sudah diganti Google, cari nama terbaru di dokumentasi Gemini (bagian Speech generation) lalu ganti SUARA_MODEL.
  • Jeda terlalu lama: ganti SUARA_MODEL ke gemini-3.8-flash-lite-tts (lebih cepat, sedikit kurang natural), atau kembali ke suara Google dengan /suara google.
  • Serial Monitor menulis penyimpanan flash TIDAK ADA: Partition Scheme masih Huge APP. Ganti ke 16M Flash (3MB APP/9.9MB FATFS) lalu upload lewat USB.
Penting

Keamanan dan privasi

  • Token bot, API key Gemini, dan API key Groq sama dengan password. Jangan unggah ke GitHub atau kirim ke orang lain. Kalau bocor, hapus kuncinya di AI Studio atau console Groq dan buat yang baru.
  • Robot hanya menurut ke chat ID-mu. Orang lain yang menemukan bot-mu akan dibalas "aku hanya menurut ke pemilikku".
  • Kamera dan mikrofon bisa merekam orang lain di rumah. Kalau dengar terus dinyalakan, setiap kalimat yang terdengar dikirim ke Groq untuk dicek apakah menyebut nama robot (paling banyak 10 kalimat per menit). Beritahu orang di rumah, dan matikan robot kalau tidak dipakai. Secara bawaan dengar terus mati: robot hanya mendengar setelah tombol BICARA.
  • Mode jaga bukan alarm keamanan sungguhan: sensor ultrasonik bisa terkecoh tirai yang bergerak, dan bisa melewatkan orang di samping.
